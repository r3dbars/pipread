For the days you’d rather listen

I built Pipread because I think every blog should have a play button. Sometimes you just want to go for a walk or make coffee and hear what someone wrote.

I also think good text to speech should be free and open. Right now, most narration on the web runs through paid cloud voice services like ElevenLabs, billed by the character. That can make sense for a big publisher. For a personal blog, it’s a lot to ask.

So Pipread keeps it simple. A small command line tool downloads an open voice model once, then narrates your posts right on your own computer. You publish the audio files next to your articles, and readers just press play.

The project also includes a simple player you can add to your blog with a code snippet. Readers can play, pause, skip ahead, or jump back. Readers can also follow along with highlighted text. Use the command line tool to generate the audio, then add the player to your page.

There’s no API key and no per-character bill. When you add or edit posts, it only redoes the ones that changed. The code is free and open source. Kokoro, an open voice model, generated the audio you’re hearing in this demo.

The idea is pretty simple. Keep writing the way you always do, add a play button, and give people one more way to spend time with your words.

Q&A

Is it really free?

The code is open source under the MIT license, apart from a few clearly marked experimental files. The voice is Kokoro, an open model released under Apache 2.0. There’s no API key and no paid speech service. Making and hosting audio still uses some computing time, storage, and bandwidth.

What do readers download?

Just an ordinary audio file and a small player. The voice model only runs on the computer where you generate the narration.

How do I add it to my blog?

Clone the source from GitHub ↗ and use Node 22.12 or newer. Run the generate command once as a dry run, then again with --write. After that it only regenerates posts that are new or changed. It’s a source-only developer preview: there’s no npm package yet, so don’t use npx pipread.

Can it run in GitHub Actions?

The same step can run in a workflow, and the repository includes an illustrative step sequence. It isn’t an installed workflow, and generation has only been validated on macOS with Apple Silicon so far.

What about making the voice in the browser?

That’s an optional local experiment that uses WebGPU, or the CPU when WebGPU isn’t available. It downloads a model on the reader’s device, and public release of that runtime is on hold.

What am I hearing in this demo?

Kokoro’s Heart voice, generated locally from this exact article. Highlighting can be turned off or follow words or paragraphs. Word timings are aligned locally to the recording; short words and pauses may not line up perfectly.

Which browsers are verified?

Chrome on a Mac, including narrow phone-width layouts. That isn’t the same as testing on a real phone, and Safari, Firefox, background playback, and offline use are still unverified.
